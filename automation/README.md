# Локальное окружение n8n

Docker-окружение для разработки автоматизации обработки заявок. На этом этапе
это только инфраструктура: workflow не создан, Supabase, Telegram и другие
внешние сервисы не подключены.

Состав:

| Сервис | Образ | Назначение |
| --- | --- | --- |
| `n8n` | `n8nio/n8n:latest` | Редактор и исполнение workflow, UI на порту 5678 |
| `postgres` | `postgres:16-alpine` | Внутренняя БД n8n: workflows, credentials, история запусков |

PostgreSQL здесь — **не** база приложения. Заявки остаются в Supabase; этот
контейнер хранит только состояние самого n8n и порт наружу не публикует.

Окружение живёт в отдельной папке `automation/` и никак не влияет на Next.js
приложение в корне репозитория.

## Запуск

Из папки `automation/`:

```bash
cp .env.example .env
docker compose --env-file .env up -d
```

Перед первым запуском откройте `.env` и замените значения-заглушки: пароль БД
и `N8N_ENCRYPTION_KEY`. Без них compose остановится с понятной ошибкой —
секреты намеренно не имеют значений по умолчанию.

Остановка:

```bash
docker compose --env-file .env down
```

## Доступ

UI: <http://localhost:5678>

При первом открытии n8n попросит создать **owner account** — локальную учётную
запись администратора (email и пароль). Она хранится в контейнерном PostgreSQL,
это не аккаунт n8n.cloud. Пароль сохраните: восстановления через почту в
self-hosted версии нет.

## Ограничение: Supabase не видит localhost

`WEBHOOK_URL=http://localhost:5678/` работает только для запросов с вашей
машины. Supabase Database Webhook — внешний сервис, и до `localhost` он
достучаться не сможет.

Когда дойдёт до реальной интеграции, потребуется публичный HTTPS endpoint
(туннель для разработки или задеплоенный n8n), а `WEBHOOK_URL` в `.env` нужно
будет заменить на этот адрес и перезапустить контейнеры. Настройка туннеля в
эту задачу не входит.

## Остановка без потери данных

```bash
docker compose --env-file .env down
```

Команда удаляет контейнеры и сеть, но **не трогает volumes**. Workflows,
credentials и история запусков остаются на месте; следующий `up -d` поднимет
окружение в том же состоянии.

## Полное удаление окружения

```bash
docker compose --env-file .env down -v
```

**Флаг `-v` удаляет volumes безвозвратно.** Вместе с ними исчезнут все
workflows, credentials, история запусков и owner account — экспортируйте нужное
до выполнения команды. Восстановить данные после этого нельзя.

## Секреты

Все значения задаются только через `.env`, который исключён из Git. В
репозиторий попадает лишь `.env.example` с заглушками.

Ключ Supabase `service_role` в это окружение сейчас не добавляется. Когда он
понадобится, храните его в n8n credentials, а не в `docker-compose.yml` и не в
переменных приложения (подробнее — `docs/supabase-processing-audit.md`).
